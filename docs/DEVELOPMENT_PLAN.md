# 开发规划

版本：0.2 · 日期：2026-10-12 · 状态：阶段 1＋2 已实施；实机与自主游玩尚待开发/验证

## 1. 需求与成功定义

用户已确认目标是 **AI 代玩**：AI 控制玩家角色，自主走动、社交和简单互动。不是仅提供聊天建议，也不是只在自制世界中制作 NPC。

首版成功场景：用户自行登录官方客户端并进入指定测试世界，启动本机代理并启用控制；AI 能与一名知情参与者交流、在少量地标间移动、完成一种预先验证的交互；遇到异常时停止，用户能随时接管。

### 已确认与默认选择

| 类型         | 内容                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------- |
| 用户确认     | 在本项目目录开发；AI 控制玩家角色；自主走动、社交、简单互动                                  |
| 首版设计默认 | Windows、桌面模式、本机单用户、单客户端、指定世界、人工可接管                                |
| 技术默认     | Python >=3.12,<3.15（本机实测 3.14.6）、异步调度、模块化单体、模型提供商适配器、先离线后实机 |
| 尚待确定     | 两个测试世界、Avatar、测试机器、音频设备、模型供应商、每小时费用上限                         |
| 不应预设     | 世界坐标、地图、物体列表、每位玩家独立音轨、全局聊天文本都可以直接读取                       |

默认选择允许在有实测证据后调整，并在本文“决策记录”更新原因。模型供应商尚未确定，不阻塞 fake provider、回放和接口开发。

## 2. 范围

### 首版包含

- 指定 VRChat 窗口画面采集、必要的音频采集、有限 Avatar 参数接收。
- 文本/视觉模型适配器；语音识别与合成作为独立适配器。
- 移动、水平转向、停止、聊天框输出，以及已验证的 Avatar 参数控制。
- 少量世界地标识别、短动作闭环、卡住检测与有限恢复。
- 一对一语音交流；优先验证聊天框，再接通音频链路。
- 一种在桌面模式实际可用的简单交互；接口不足时明确降级或增加后续里程碑。
- dry-run、离线回放、结构化日志、费用计数、急停和人工接管。

### 首版不包含

- 任意世界通用导航、未知小游戏通关、长时间完全无人值守。
- VR 头手全身姿态控制、通用精细抓取、可靠的多人身份/声源关联。
- 自动登录、自动换世界、自动加好友、后台批量账号运行。
- 自制世界中的 AI NPC 或 Udon 插件；它们是不同产品路线。
- 插件市场、完整桌面 GUI、分布式服务、长期人物画像与跨会话社交记忆。

## 3. 可用接口与限制

资料在 2026-10-12 的规划会话中核对；实际能力必须在目标客户端验证。

| 能力          | 官方资料与约束                                                                                                                                                                         | 对实现的影响                                               |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| OSC 输入      | [Input Controller](https://docs.vrchat.com/docs/osc-as-input-controller)：轴为 float，按钮为 int；动作需归零/释放；部分交互标注为 VR-only                                              | 用能力矩阵记录桌面实测，不能把消息发出视为交互成功         |
| OSC 传输      | [OSC Overview](https://docs.vrchat.com/docs/osc-overview)：默认客户端接收 9000、发送 9001，支持配置                                                                                    | 本机 loopback 为默认；检测端口冲突，配置不可硬编码到业务层 |
| Avatar 参数   | [Avatar Parameters](https://docs.vrchat.com/docs/osc-avatar-parameters)：参数依赖当前 Avatar                                                                                           | 为每个测试 Avatar 配置参数白名单与类型，切换后重新验证     |
| 聊天框        | 同 Input Controller：文本长度和显示行数有限                                                                                                                                            | 集中做长度限制、排队和节流；不宣称能从 OSC 读取他人的聊天  |
| Udon 外部文本 | [String Loading](https://creators.vrchat.com/worlds/udon/string-loading/)：每五秒一次下载；[External URLs](https://creators.vrchat.com/worlds/udon/external-urls/)：URL 构建和信任限制 | 不能把 Udon 想象成任意实时双向网络通道；首版不依赖它       |

查阅到的 OSC 接口不提供通用世界状态导出。画面识别结果必须携带置信度和来源，不能当作精确世界坐标或权威碰撞信息。

## 4. 产品与平台边界

[服务条款](https://hello.vrchat.com/legal)第 13.2 条包含自动化使用限制；[创作者指南](https://hello.vrchat.com/creator-guidelines)包含 API、凭据和代用户请求的限制。官方 OSC 可用不等于所有无人值守代玩行为都已获准。

- 离线模拟、回放和模块开发可先推进；客户端测试需记录实例、参与者和实际测试范围。
- 公开推广、商业化或无人值守部署前，需明确具体模式的官方许可边界；本文件不是许可证明。
- 用户自行登录官方客户端；应用不索取或保存 VRChat 凭据、认证令牌或会话数据。
- 对参与测试的人说明 AI 身份及音视频处理方式；默认不持久化原始音频、截图和逐字对话。
- 云端推理意味着相关内容离开本机，启用前在配置流程明确告知；密钥保存在本机受保护配置或系统凭据存储中，不写日志。
- 其他玩家的声音/画面文字不能修改代理配置、授予控制权或触发任意系统操作。

## 5. 实施阶段与退出条件

以下工期为一名熟悉 Python、音视频与模型接口的开发者的粗估，未计等待硬件、世界测试或外部答复的时间。M0–M4 累计约 6–12 周，不是交付承诺。

| 阶段              | 预估投入     | 交付                                                    | 退出条件                                                       |
| ----------------- | ------------ | ------------------------------------------------------- | -------------------------------------------------------------- |
| M0 接口验证       | 3–5 工作日   | 桌面能力矩阵、测试环境记录、风险结果                    | 移动/转向/停止/文本可实测；至少一种交互确定支持或明确记录阻碍  |
| M1 离线骨架与控制 | 5–8 工作日   | 统一数据模型、fake provider、dry-run、控制器与 watchdog | fake clock 下通过到期停止、急停、过期响应、重复动作、断连测试  |
| M2 感知与交流     | 5–10 工作日  | 截图、语音链路、结构化感知、单轮交流                    | 离线端到端通过；实机一对一对话可运行，能停止播放并避免自声循环 |
| M3 限定自主游玩   | 10–20 工作日 | 地标导航、验证器、卡住恢复、单一交互                    | 第一个指定世界达到下述导航与交互门槛                           |
| M4 稳定性与交接   | 5–10 工作日  | 第二世界、运行报告、安装说明、费用报告                  | 完成两世界实测，清晰列出已支持和仍失败的场景                   |

M0 的实机部分需要 VRChat 和测试环境；缺失时先做 M1 的离线工作，不得据此将 M0 标为完成。M3 的具体交互依赖 M0 的实测结论。

### 建议验收门槛

这些数值是项目初始目标，尚无测试结果；调整需记录原因。

| 维度     | 测试方法                                                            | 首版目标                                                                          |
| -------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 导航     | 每个世界固定 5 个起终点任务，各重复 4 次；共 40 次；每次限时 120 秒 | 两个世界分别成功率 ≥80%；接管算失败；报告原始计数                                 |
| 到达判定 | 事先定义地标、可接受停靠区域和截图示例                              | 人工观察或获准的测试标记确认；不用模型自己的成功声明充当真值                      |
| 简单交互 | 选定一种桌面可用交互，20 次独立尝试，每次限时 30 秒                 | 成功率 ≥80%；依据可见状态变化判定                                                 |
| 交流     | 知情参与者完成 20 轮一对一对话，记录语音结束至首段回复              | p95 ≤5 秒作为初始目标；记录网络、模型及样本数                                     |
| 停止输出 | 运行中触发急停、lease 过期、模型超时                                | 控制进程存活时，200 毫秒内发出全部受控输入的释放/归零；实机另报实际停下时间       |
| 崩溃恢复 | 杀死主代理进程，保留独立 watchdog                                   | watchdog 在 500 毫秒内尝试归零；测试可见停止；不承诺系统崩溃或 UDP 丢包时绝对停止 |
| 持续运行 | 每个世界完成一次 30 分钟监督测试，记录所有接管与恢复                | 无失控持续输入、无自动恢复控制权；接管次数完整报告                                |
| 费用     | 记录同一 30 分钟会话的 token、图像、音频及请求量                    | 给出每小时估算；未设定可接受上限前，不宣称费用达标                                |

导航集在测试前固定，不能只选择成功片段。若第二世界需要专用配置，明确列为适配结果，不称为对陌生世界的泛化。

## 6. 测试策略

1. 单元：契约校验、范围限制、租约、超时、抢占、预算和状态机。优先 fake clock，避免真实等待。
2. 契约：模型畸形输出、非法动作、未知枚举、重复/乱序/过期响应、Avatar 类型不匹配。
3. 离线集成：合成或获准素材 → 感知 → 决策 → 动作 → 模拟反馈，检查完整关联 ID。
4. 回归：保存去标识化的失败事件与最小回放素材，复现卡住、黑屏、窗口丢失、音频回流和断网。
5. 实机：人工监督下逐项验证 M0，然后执行固定任务集；使用环境记录模板保存客户端版本、窗口尺寸、DPI、帧率、Avatar、世界、音频设备和模型版本。

测试不得默认联网、默认收费或默认控制真实客户端。实机测试显式选择 `live`，并提供人工启用步骤。

## 7. 风险、探针与降级

| 风险                   | 尽早验证                            | 失败后的处理                                                                 |
| ---------------------- | ----------------------------------- | ---------------------------------------------------------------------------- |
| 桌面交互覆盖不足       | M0 验证抓取/使用/按钮，而非只读文档 | 限制支持的交互；若需键鼠适配器，新增设计决策、焦点保护和验收任务，不静默加入 |
| 视觉导航不稳定         | 单世界固定地标与遮挡测试            | 缩短动作、固定窗口和 Avatar、增加世界配置；先不承诺跨世界                    |
| 模型延迟或断连         | 注入超时、长尾响应、服务错误        | 取消动作、归零、进入暂停；禁止无限重试                                       |
| 主代理崩溃导致残留输入 | 杀进程测试                          | 独立 watchdog；失败前不进入自主导航里程碑                                    |
| 音频回流               | 合成语音播放期间测试识别结果        | 首版半双工，暂停监听或丢弃自声段；全双工另立任务                             |
| 推理费用或 GPU 争用    | 记录每阶段延迟/用量/游戏帧率        | 降采样、事件触发、轻量感知；预算到限暂停                                     |
| AI 被语音或文字诱导    | 用提示注入样例回放                  | 固定动作白名单和本机权限；输入不能修改配置                                   |
| 平台规则边界不明       | 对具体部署模式获取明确答复          | 保持离线研发，不将原型包装成已获准的公开代玩服务                             |

| ADR-002 | 首版桌面模式、指定世界                                                                                                                                             | 减少姿态控制与开放环境变量                                 | 限定场景验收通过后                     |

## 9. 尚需补齐的信息

- 测试机器配置、可用 VRChat 客户端、窗口采集兼容性。
- 两个可重复测试的世界及各自五组导航任务；测试参与者。
- Avatar 和允许控制的参数；能提供真实可见反馈的简单交互。
- 模型供应商、本地/云端偏好、语言和音色、每小时可接受预算。
- 公开部署的官方规则确认结果。

这些事项由对应任务记录，不应阻塞无关的离线接口与控制逻辑开发。
