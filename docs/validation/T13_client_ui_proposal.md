# T13 本机客户端提案（2026-10-18）

状态：**提案，未实现、未排期**。本文只描述设计与边界，不是实现授权，也不是实机验收。
来源：用户在会话中提出"启动后就是一个清晰的客户端 UI，能检测 VRChat 是否启动、让用户选择是否连接 AI，并看到运行状态与控制"。

## 1. 目标形态

双击启动 → 自动体检 → 用户显式选择"连接 AI" → 运行面板。

```mermaid
flowchart LR
    A[启动客户端] --> B{检测 VRChat}
    B -- 未运行 --> B1[提示并允许重试]
    B -- 已运行 --> C[环境体检：进程/窗口/可见性/分辨率与 DPI]
    C --> D{配置与标定就绪?}
    D -- 否 --> D1[选择任务/世界版本/模型<br/>勾选付费与发送图像授权]
    D -- 是 --> E[显示"连接 AI"]
    E --> F[连接：启动主代理与控制进程]
    F --> G[运行面板]
```

体检项全部来自现有采集能力，不需要新产品能力：进程是否存在、窗口标题是否为 `VRChat`、窗口是否可见/未被遮挡、分辨率与 DPI、Unity 窗口类、当前世界与姿态是否匹配冻结世界。

## 2. 运行面板内容

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| 环境 | VRChat 状态、分辨率、DPI、世界版本、标定摘要 | 体检 + 冻结世界 |
| 状态 | `DISARMED`/`ARMED_IDLE`/`EXECUTING`/`PAUSED`/`ESTOP` | 控制进程 `status` |
| **租约** | **大字倒计时进度条**、已续租次数/上限、控制窗口剩余 | `lease_expires_ns`、`control_budget` |
| 任务 | 任务 ID、组别、步数 n/40、剩余任务预算 | 运行时 + 策略 |
| 最近动作 | 类型、参数、是否在 1 s TTL 内被接受 | 动作与结果 |
| 最近拒绝 | `stability_precheck` / `stability_rejected` 的原因与像素证据 | 事件流 |
| 花费 | 本次调用数、token、金额、成本是否完整 | 报告 `usage` |
| 事件流 | 可折叠时间线（预检/推理/校验/提交，含分阶段耗时） | `stage_timing` 事件 |

租约倒计时是重点：第 81 节 pilot3 的 `ARM_TIMEOUT` 说明"该按 F9 了"这件事在纯终端里不够显眼。

## 3. 安全边界

**不得突破**：

1. 客户端永不直接写 OSC；所有动作仍经独立控制进程校验。
2. live 的 ARM/RESET/续租仍以本机热键为准；UI 不得成为绕过通道（第 80 节已证明 `Command.operation` 闭集与 IPC 拒绝）。
3. UI 断开即停：本地连接断开时主代理按现有心跳规则 `stop("HEARTBEAT_LOST", emergency=True)`。
4. 急停、动作到期归零、epoch、TTL、租约基础时长与续租上限均不变。

两种形态：

| 形态 | 能力 | 安全影响 | 前置 |
| --- | --- | --- | --- |
| A 监控 + 引导 | 显示全部状态；控制按钮只提示"请按 F9 / Ctrl+F9 / F8" | 无 | 可立即做 |
| B 本地受信控制 | 按钮真正触发 ARM/续租/急停 | 需内核识别"本地交互来源"并执行同样前置检查 | 新版本 + ADR-009 复核 |

形态 B 的设计要点（供将来复核）：

- 来源必须是本机交互会话（例如仅回环 + 用户目录内令牌 + 单实例锁），不得来自 IPC 广播或模型请求。
- 前置检查与热键分支完全相同：焦点、按钮释放、未急停、未过期、次数与总预算。
- 每次 UI 触发的 ARM/续租/急停都要落独立事件，报告可重算，与热键路径可区分。

## 4. 技术选型建议

| 方案 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- |
| 本地 Web UI（localhost 回环 + 静态页面） | 零新依赖、迭代快、跨平台 | 无原生窗口 | **先做 P1** |
| PySide6 桌面窗口 | 真桌面程序、可打包 | 新增重依赖与打包成本 | 界面定稿后再评估 |
| Tauri / Electron | 观感最好 | 引入 Node 生态、与 Python 栈割裂 | 不建议 |

## 5. 分期与验收

| 阶段 | 内容 | 前置 | 验收标准（提案） |
| --- | --- | --- | --- |
| P1 | 启动检测 + 只读状态面板 + 租约倒计时 + 事件流 | 无 | 未启动/已启动/被遮挡三种状态提示准确；倒计时误差 ≤0.5 s；UI 断开 ≤1 s 进入 PAUSED；无 UI 时 CLI 与热键行为不变 |
| P2 | 任务选择、历史报告、成本统计 | T10 收口 | 报告与 `report` 命令口径一致，不重算、不估算缺失值 |
| P3 | UI 内本地受信控制 | P1/P2 稳定 + 安全复核 | 与热键路径前置检查等价；伪造/越权请求被拒并留事件 |

## 6. 风险与未决问题

- **R1 双入口风险**：形态 B 若实现不当会成为绕过热键的通道 → 必须复用同一校验函数并独立复核。
- **R2 状态不一致**：UI 自缓存导致显示与实际租约不符 → 只以控制进程 `status` 为准，倒计时由截止时间本地推算并定期校准。
- **R3 遮挡采集**：UI 常驻前台可能遮挡 VRChat 导致采集失败 → 需最小化/置顶策略说明，并在体检里提示。
- **R4 分发与凭据**：UI 不得保存 API key，继续依赖用户环境变量；打包后需说明存储位置。
- **未决**：是否允许 UI 直接"选择任务并启动"（还是只显示 CLI 命令）；P1 是否要求无边框窗口；是否需要托盘常驻。
