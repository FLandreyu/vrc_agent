## 3. 失败模式解读（数据支持；逐对位置未记录）

- **全局 >1%**：活跃姿态下持续 1.5–2.1%。主要贡献是**未遮罩的镜中角色/粒子簇与场景环境动画**（v2 设计文档已预判"镜中动画若集中…v2 仍拒绝，G3 等任务可能无法完成"；现场确认且波及多组姿态）。用户自身头像的呼吸/摆动等环境动画在相应视角同样计入。
- **局部单块 25–926**：安静姿态下也存在。单块 926 ≈ 30×30 像素整块变化（非抖动）；来源含**遮罩外的客户端 UI 碎块**（§39 实测 UI 活动延伸到 x≈2048、y≈0–520，而 v2 遮罩只覆盖到 x=1856）与小动画簇。
- 位置缺口：本轮未记录逐对变化区域坐标；若要直接支持 v3 的区域/阈值设计，可补一次 5–10 分钟的定位采集（复用动态块图探针）。

## 4. 对修订的直接影响（供实现者提案、复核者对抗）

- v2 的"保守多层"对真实场景**过度敏感**：最安静条件下仍有单块 >15；镜像/角色可见姿态下全局 >1%。运行时按此判据预热会几乎必然 `WARMUP_UNSTABLE`。
- 与 §39 的真实移动信号（61–93%）相比，环境动画上限约 2.1%：全局阈值在 3–5% 区间有 ≥15 倍余量可选；局部判据需要**重新设计形态**（单块上限、连通簇尺度、或区域化）或扩展区域策略（覆盖 UI 全列/镜面簇——镜面是 G3 任务目标区，须论证不遮挡导航证据；`MASKED_SCENE_EVIDENCE` 语义不变）。
- 预热度量耗时现实：warmup ≥3 帧 + 2 次比较 ≈ 2s+；叠加 3.5s 推理与后置复核，30s 任务可用动作数进一步缩水。
- 纪律：现场不得就地放宽任何阈值；修订须新版本（新 JSON + 新摘要）+ 独立复核 + 新的现场复验。
